# 前端设计规范：消息网关控制台

> 本规范按已安装的 `frontend-design:frontend-design` skill 制定。当前为设计计划，尚未生成页面代码。
>
> 需求已收敛为低并发“设备回调数据测试台”。四个功能独立、原始数据查看和简化布局以 [TEST_CONSOLE_OPTIONS.md](TEST_CONSOLE_OPTIONS.md) 为准；本文中的发送管理、复杂工作台和用户角色不再作为当前首版范围。

## 1. 产品、用户与主要任务

- **产品**：短信/彩信网关运营控制台，而不是通用 SaaS 数据看板。
- **用户**：需要快速判断设备与 SIM 端口是否可用、追踪短信是否送达、查看收到的短信和彩信的运营与技术人员。
- **主要任务**：先发现异常端口或失败发送，再从事件进入对应的号码、任务、回执或彩信详情。
- **设计主题**：**信号机架**。视觉来自设备面板、SIM 插槽、端口编号和状态灯，把“端口矩阵”做成系统最有辨识度的核心，而不是套用一排统计卡片。

界面用词从用户任务出发：使用“发送短信”“查看回执”“下载附件”，不使用“触发 webhook”“执行适配器”等实现术语。

## 2. 设计令牌

### 2.1 色彩

| 名称 | 色值 | 用途 |
|---|---|---|
| 机架墨色 `#16262E` | 主文字、导航、重要边框 | 呼应设备外壳，提供稳定对比 |
| 机箱雾灰 `#EEF3F4` | 页面底色、分组底色 | 冷调浅灰，不使用常见的暖米色背景 |
| 面板白 `#FFFFFF` | 主工作区、表格详情 | 给密集信息留足清晰空间 |
| 载波青 `#007C83` | 主操作、在线状态、当前选中 | 唯一的品牌强调色 |
| 信号琥珀 `#B26A1B` | 待发送、状态过期、注意 | 与错误区分 |
| 告警砖红 `#B5473C` | 发送失败、端口异常、破坏性操作 | 仅用于需要处理的状态 |

辅助文字使用机架墨色的透明度派生色，不额外增加一组灰色。成功不另用鲜绿，与载波青统一；错误也不依赖颜色单独表达，必须同时提供图标和文字。

不使用渐变装饰、大面积近黑底配酸性绿或统一圆角卡片套件。

### 2.2 字体

- **中文与界面**：`Noto Sans SC`（思源黑体同源），400/500/700 三档字重。
- **设备标识**：`IBM Plex Mono` 仅用于 TID、IMEI、ICCID、端口号和精确时间戳。这些是真正需要等宽对齐的数据，不把等宽字体当作泛用装饰标签。
- **标题**：700 字重，紧凑但不使用全大写英文 eyebrow；正文 14–16 px，表格数据 13–14 px。
- 正文行高 1.6，单行文本控制在 80 个字符以内；长短信正文允许自然换行并保留空白符。

### 2.3 空间与形状

- 4 px 基础间距，常用间距 8/12/16/24/32。
- 主工作区最大宽度 1600 px，表格可横向滚动，手机端切换为记录摘要。
- 面板圆角 6 px，输入框和按钮 4 px；端口单元使用小圆角和明确插槽分隔，不把所有内容做成相同卡片。
- 阴影只用于浮层和菜单。普通内容通过留白、分隔线和层级底色组织。

## 3. 布局概念

### 3.1 工作台：先看到真实设备，而不是抽象数字

```text
┌──────────┬──────────────────────────────────────────┬────────────────────┐
│ 消息网关  │ 设备名称 / 最后同步 / 刷新               │ 当前用户           │
│          ├──────────────────────────────────────────┤                    │
│ 工作台    │ 端口矩阵（8/16/32 口按真实设备排列）      │ 需要处理           │
│ 收件箱    │ ┌────┐ ┌────┐ ┌────┐ ┌────┐             │ 3 个端口状态过期    │
│ 彩信      │ │1.01│ │1.02│ │1.03│ │1.04│  …          │ 5 条发送失败        │
│ 发送任务  │ │在线│ │无卡│ │弱信号│ │在线│             │                    │
│ 设备端口  │ └────┘ └────┘ └────┘ └────┘             ├────────────────────┤
│ 回调记录  ├──────────────────────────────────────────┤ 最新事件           │
│ 系统设置  │ 今日收发概况（紧凑单行，不做大型 KPI 卡） │ 时间 / 类型 / 摘要  │
└──────────┴──────────────────────────────────────────┴────────────────────┘
```

- 左侧导航稳定，主内容左对齐；端口矩阵按照真实设备行列对齐。
- 右侧事件栏只显示需要行动或最新变化的内容，点击后进入详情，不设置无意义的箭头按钮。
- 选中端口时，在矩阵下方展开状态、近期短信和发送记录；上下文不跳转丢失。
- 手机端右侧事件栏移到矩阵之后，端口矩阵保持可横向滚动，避免把端口号压缩到不可读。

### 3.2 收件箱与彩信

```text
┌─────────────────────────────────────────────────────────────────┐
│ 收件箱                                                           │
│ 搜索号码或正文   设备/端口   时间范围   更多筛选                  │
├───────────────────────────────┬─────────────────────────────────┤
│ 发件人 / 正文摘要 / 端口 / 时间 │ 完整短信或彩信                  │
│ 发件人 / 正文摘要 / 端口 / 时间 │ 发件人、接收人、SMSC、SCTS       │
│ 发件人 / 正文摘要 / 端口 / 时间 │ 彩信正文、图片附件、附件信息     │
└───────────────────────────────┴─────────────────────────────────┘
```

- 列表选择后立即更新详情，详情保留筛选上下文。
- 图片以适合查看的尺寸显示，下载按钮明确写出“下载原图”或“下载附件”。
- 原始请求内容放在“技术详情”折叠区，默认隐藏敏感信息，不与用户正文混在一起。

### 3.3 发送任务

- 发送页采用单栏步骤流，仅在真实顺序内容中使用编号：填写收件人与内容 → 选择端口 → 检查并发送。
- 任务列表的进度条按号码状态分布，悬停或键盘聚焦显示准确数量。
- 任务详情先给失败原因筛选，再给号码明细，避免运营人员逐条寻找失败号码。

## 4. 关键组件

### 端口单元

每个单元必须同时显示端口号和文字状态；SIM 号码默认脱敏。信号强度使用短横线阶梯与文本值，不用无法区分的纯颜色灯。

```text
┌──────────────┐
│ 1.03    弱信号│
│ 96••• •••287 │
│ Asiacell     │
│ ▂▂▂──  9     │
└──────────────┘
```

### 状态文字

统一使用“已注册、注册中、无 SIM、注册失败、已锁定、状态过期”等业务语言；技术详情保留原始 `st` 值，避免用户自行背状态码。

### 操作反馈

- 发送按钮写“发送短信”，成功后提示“发送任务已创建”，不能把设备已受理误写为“全部送达”。
- 导入按钮写“检查历史文件”，dry-run 后再出现“确认导入”。
- 空收件箱：“还没有收到短信。新短信到达后会显示在这里。”
- 无搜索结果：“没有符合这些条件的短信。清除部分筛选后再试。”
- 回调错误：“无法解析这条回调。检查内容类型和字段格式，原始内容已保留。”
- 状态过期：“该端口超过 10 分钟没有上报，当前显示的是最后一次状态。”

## 5. 动效与可访问性

- 首次加载不做逐卡片淡入；只允许端口矩阵一次简短的整体显现。
- 当用户刷新或收到新事件时，仅更新发生变化的端口和事件行，动效 150–200 ms。
- 尊重 `prefers-reduced-motion`，关闭非必要移动和状态闪烁。
- 所有操作可用键盘完成，焦点样式清晰；表格、端口单元和进度条提供可读名称。
- 正文和交互颜色达到 WCAG AA 对比度；触屏目标至少 44×44 px。
- 手机端不隐藏关键失败原因和端口状态，筛选器折叠后仍显示已生效条件。

## 6. 设计自检与已做的修订

在写页面代码前，按 skill 要求进行以下反模板检查：

1. **把默认的“四个大数字卡片”改成真实端口矩阵。** 理由：端口状态是这个行业最独特、最可操作的信息，统计数字降为辅助。
2. **不使用暖米色 + 陶土色或黑底 + 酸性绿。** 改用冷调机箱雾灰、机架墨色和载波青，来源是实际硬件与载波状态。
3. **不用全大写标签、装饰性编号和满页箭头。** 编号仅用于发送步骤，按钮直接描述动作。
4. **等宽字体只服务真实设备标识。** 不把它用作所有小标签的默认风格。
5. **大胆之处只保留端口矩阵。** 其余表格、详情和表单保持克制，去掉无业务含义的装饰。
6. **使用真实业务文案。** 页面围绕 `1.03`、TID、SCTS、失败原因、最后上报时间等信息设计，不使用泛用的“提升效率”“数据赋能”。

这份规范后续用于页面实现与截图复核；如果实现后出现相同卡片重复堆砌、装饰多于信息或移动端不可读，应优先删减而不是继续添加视觉效果。
